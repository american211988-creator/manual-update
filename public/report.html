개별 수정 확인(Mac 한글 파일명, Word 표 칸 비교, 조사 분리 강조)은 해당 파일을 직접 내려받아 확인. 추가로 화면·워드·엑셀에 표시되는 현행/개정 문구가 원문과 같은지 95건 전수 검사(불일치 0), 자동 비고 56건 문구 검토.

검증 방법

  1. 정답(기대값)은 앱과 따로 계산: 변경 정답표는 생성 스크립트의 변경 목록에서, 조항 수·변경률·알림 대상·집계는 tools/make_expected_metrics.py로 계산 (샘플은 원문 파일을 직접 읽어 셈).
  2. 시험용 자료 생성: 변경 목록(무엇을 어떻게 바꿨는지)에서 신구 문서와 정답표를 함께 만들어, 문서와 정답이 어긋나지 않게 함 (tools/make_test_pack*.py).
  3. 앱의 ‘기준 데이터’에 문서 메타·정답표 CSV를 올리고, 문서를 문서함에 한꺼번에 끌어다 놓음.
  4. ‘전체 신구 비교 실행’ 후 ‘정답 검증’ 탭의 건별 대조로 판정.
  5. 실행 환경: 운영과 같은 빌드(public/index.html)를 Chromium 브라우저에서 자동 조작.

재현 자료: 저장소 data/test_pack/, data/test_pack2/ (각 README에 넣는 순서). 앱: manual-update.vercel.app

한계와 다음 단계

  • 시험 자료가 모두 가상 문서입니다. 같은 규칙으로 만든 문서라 실제 사내 문서보다 정형적입니다. 실제 문서 기준 정확도는 아직 확인하지 않았습니다.
  • 분류는 키워드 방식입니다. 제목·본문에 ‘사무처리’, ‘매뉴얼’, ‘내규’ 같은 말이 없으면 ‘미분류’가 됩니다. 키워드는 ‘기준 데이터’에서 CSV로 바꿀 수 있습니다.
  • 조항 번호를 새로 매긴 개정은 같은 조항이 ‘삭제 + 신설’로 잡힙니다.
  • PDF는 만든 프로그램에 따라 줄바꿈·띄어쓰기가 다르게 읽힐 수 있고, 스캔 이미지 PDF는 읽지 못합니다.
  • 작업 내용은 각 브라우저에만 저장됩니다. 저장 공간이 부족하면 화면 위에 경고가 뜹니다(대용량 파일 10개 업로드 후 새로고침해도 유지 확인).
  • 알림은 화면 안에만 쌓이며 각 사용자 브라우저에 저장됩니다(실제 발송 없음, 기획서 범위).
  • 자동 비고는 문구 차이 요약입니다. ‘현금 지급 폐지’처럼 뜻을 요약하지는 않으므로 필요한 곳은 담당자가 고쳐 저장합니다.

다음 단계: 실제 개정된 사내 문서 1~2쌍으로 담당자 수작업 대비표와 앱 결과를 대조하고(누락·오분류 건수), 같은 건의 작성 시간을 비교해 기획서 판정 기준(정확도 90% 이상, 소요 시간 50% 이상 단축)을 확인합니다.
